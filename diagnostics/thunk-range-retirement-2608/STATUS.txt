Critical v1 flaw discovered during source audit:
- Compiled CustomIR entrypoints are inserted with an empty CodePages vector because GenerateIR takes the CustomIR path before normal frontend decoding/page registration.
- GuestToHostMap::InvalidateRange() finds shared/L3 blocks only through CodePages.
- LookupCache::InvalidateCacheRange() finds thread-local L1/L2 entries only through CachedCodePages.
- Therefore InvalidateGuestCodeRange(H, 1) cannot be trusted to evict an already-compiled synthetic CustomIR entrypoint H. The previous ablation's "invalidate H" axis was not a real exact-H invalidation.

Interpretation:
- The real-FEX baseline retains generation-1 ownership across unload, exactly as predicted by the CustomIR lifetime hypothesis.
- Exact retirement plus exact shared/per-thread H eviction is causally positive: it removes enough generation-1 state for the stable H identity to bind and execute generation 2 cleanly.

Compile repair discovered by first A/B run:
- The first v2 build failed because CodeBuffer::LookupCache is GuestToHostMap*, while the draft called a helper added to the per-thread LookupCache class.
- The repair performs shared/L3 exact eviction directly with GuestToHostMap::AcquireWriteLock() plus GuestToHostMap::Erase(H, lock).
- Per-thread exact L1/L2 eviction remains on LookupCache.

v2 causal experiment semantics:
1. Add exact shared/L3 eviction for a synthetic entrypoint H via GuestToHostMap::Erase(H), which also delinks inbound direct block links.
2. Add exact per-thread L1/L2 eviction for H and flush the call/return shadow cache.
3. Scan CustomIRHandlers for thunk-owned entries whose Data guest target T lies in a successfully unmapped guest range.
4. Erase those H->T registrations and exact-evict every returned H under the same code-invalidation transaction.
5. Invoke the retirement after successful GuestMunmap and before ordinary guest-range invalidation.

Known limits of v2:
- GuestMunmap has already performed the kernel unmap before v2 retirement; this is a causal probe, not a race-safe lifetime protocol.
- Peer threads already executing a translated H block are not quiesced.
- Host-to-guest callback trampolines are not retired.
- mmap(MAP_FIXED), mremap, shmdt, and other destructive mapping paths are not covered by this first probe.
- No load-generation/owner identity is attached to H->T registrations yet.
- The informational retirement log did not appear in the successful run's stderr, so the runtime A/B behavior is the primary discriminator; future instrumentation should use an explicit receipt/counter rather than relying on normal logging configuration.
